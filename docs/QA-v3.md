# v3.0 自由战役验收记录

日期：2026-10-12。测试环境：Windows、本机 Node、Codex 内置 Chromium 浏览器；本地测试源为 `http://127.0.0.1:43992/`。

## 规则与构建

- 60 项 Node 行为测试通过，包含 17 项自由战役测试，旧版 43 项测试保留。
- 覆盖十二城道路、敌城截断、独立逐日调动、中立接管、驻守、协同进攻、攻守胜败、撤回、兵员/城防费用、动态战场、占旗目标与战损。
- 30 个种子各执行 100 次下令/推进/结算，共 3,000 次状态转换，每次导出再严格导入，校验待决战斗与实际军团兵力一致。发现并修复了连续战斗使用旧兵力、敌军同时攻守，以及高守备在每日修整时下降的问题。
- 静态构建包含 campaign-core.js、campaign.js、campaign.css，不依赖运行时包或外部 API。

## 浏览器实际操作

- 三军团分别下令：第一军团攻武汉，第二军团接管西安，第三军团接管广州。推进一天后，军团位于实际目标/原攻城位置，中立城转为我方，武汉生成待决攻城战。
- 武汉河桥攻城：开场暂停，三队分别安排前往旗帜，再开始；实际胜利，生命保留 82%，城市归我方，军团入城，战损同步。刷新后城与兵力保留。
- 武汉加固至二级，第 4 天遭到东部军团反攻。直接点蓝色部队和红色敌军，DOM 命令为 attack；暂停布阵后守城胜利，生命保留 88%。
- 同一天西安快速结算守住；广州选择撤离，归属变为敌方，第三军团退回昆明。军团补给、兵力、敌军位置和日志随结果更新。
- 自由选择下一目标南京，生成城镇攻城与二级城防堡垒；三队行军并实际胜利，生命保留 65%，军团入城。没有按旧三场教学顺序推进。
- 第二军团离开西安后，西安遭反攻时显示当地守备队参战，无需场上军团也能亲自指挥。
- 弱守备实战：步兵生命从 63 降至 24；请求救护恢复至 63，补给从 260 降至 245，救护按钮禁用。战中撤离后西安实际失守，之后继续处理昆明的待决守城。
- 导出真实第 5 天 JSON，包括南京待决战、军团路线与位置；文件通过严格模型校验，重新导入成功。兵力被篡改至 99999 的文件拒绝导入，现有第 5 天战役保持；刷新自动恢复南京待决选择。
- 390×844 窄屏：页面可用宽度与 scrollWidth 同为 375，无横向溢出；选择第二军团，通过目标城市下拉框调往成都并推进一天，军团实际抵达成都。
- 玩法切换保留独立存档：前线冒险五场景/七条电话线路仍可打开，经典经营欢迎页可进入，回到自由战役后继续原战果。
- 本地浏览器控制台未发现 error/warn。

## 范围

这里记录的是浏览器运行与模型验证，不等于手机硬件或用户手感验收。自由战役采用固定十二城道路图与动态攻守遭遇，没有随机地图编辑器。未结算的实时战斗刷新/切换玩法后重新集结，已经结算的占城与战损不会重复记账。三种玩法的经济与角色探索进度独立。

公开部署由同仓库 GitHub Actions 执行测试、构建与 Pages 发布；发布状态与匿名网页资源在此次交付时另行在线核验。
