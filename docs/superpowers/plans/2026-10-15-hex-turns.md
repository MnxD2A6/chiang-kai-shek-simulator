# Hex turns execution plan
Spec: ../specs/2026-10-15-hex-turns-design.md
Execution: native in the existing dedicated publishing checkout, branch codex/hex-turns-2-0. User explicitly requested implementation and publication. Existing assets pipeline is sufficient; no paid generation.

1. Hex topology: new counteroffensive/hex-grid.js exposes at(lon,lat), cell(key), neighbors(key), distance(a,b), route(from,to,allowed), nearestSea(key). Axial coordinates, radius0.6 in geographic Mercator projection, six neighbors. Test geometry roundtrip, coasts/cities and land/sea paths before implementation.
2. Turn engine: hex-core.js owns state, command dispatch, previews, AP, transport, combat, deterministic enemy actions, warning schedules, results and independent validated save format. hex-world.js adapts existing event data and all effect types to turns. Tests first: no wall-clock changes, AP limits, once-per-turn attack, invalid/no-resource mutation, cargo and sinking, 2-turn military hold, explicit defeats, event response/no advancement, nuclear consequences and truce, import rejection.
3. Map and UI: hex-map.js draws existing geography/art with hex selection/reachability and view-only animation. hex-app.js owns DOM/render/storage/event flow; hex-ui.css responsive black/cream/orange interface. Archive index as realtime.html and use new index for 2.0. Tests cover assets/build entry and old-save separation; browser exercises actual clicks, mobile reachability and event illustration.
4. Balance and review: test reproducible command strategies without forging resources; actual browser new campaign through victory, keep earned saves/screenshots/turn decisions. Review whole branch with a fresh read-only reviewer, repair material findings and rerun appropriate checks. Record limits honestly, especially 10–20 minute target versus actual player thinking time.
5. Release: package versions/README/QA; 177 legacy checks plus new suite, both builds, clean diff. Push existing main with user authorization, await Pages success, compare public files to committed blobs, browser verify version/control/illustration. Sync current source mirror, preserve old archives, create 2.0 source/web archives and verify CRC/content, keep public deliverable tab.

Review focus: AP cannot be spent twice by UI, pending news cannot skip enemy turns, carriers release dead cargo, no attacks on friendly/neutral targets, save data cannot forge coordinates/foreign occupation/terminal results.
